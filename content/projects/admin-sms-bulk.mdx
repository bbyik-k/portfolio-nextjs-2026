## 📌 프로젝트 개요

- 대량 문자 전송 플랫폼의 ==통계 및 포인트 관리 어드민==입니다.  
  수기로 제공하던 고객 통계 자료를 웹 화면으로 대체하도록 구현하였습니다.
- 문자 송신 ==통계 조회==, ==포인트 조회 및 충전==, ==엑셀 다운로드== 기능을 제공합니다.
- 마스터, 일반 사용자, 시스템 ==3단계 권한==에 따라 접근 메뉴와 조회 범위가 달라지도록 구성하였습니다.
- 발주사 백엔드 개발자와 ==API 규격을 협의==하며 진행한 외주 프로젝트로, 프론트엔드를 단독으로 담당하였습니다.

## 🧑‍💻 주요 기여

### API 규격 협의 및 연동

- 백엔드가 초안한 규격을 검토해 [[불필요한 응답 중첩 제거]],  
  [[GET+Body 조합을 POST로 통일]]할 것 등을 제안하고 반영하였습니다.
- 응답 데이터 중복, 권한 코드 체계 등 [[규격 오류를 사전에 발견]]해 수정을 요청하였습니다.
- 새로고침 시 로그인이 풀리는 문제에 대해 저장 방식을 제안하여,  
  [[인증 갱신 API]]가 신설되도록 하였습니다.

### 데이터 시각화 및 다운로드

- [[Nivo Chart]]로 원형 및 선형 차트와 이통사별 집계 표를 구성하고,  
  고객사와 조회 기간 선택에 따라 갱신되도록 구현하였습니다.
- [[xlsx 라이브러리]]로 통계 표를 엑셀 파일로 내려받는 기능을 구현하였습니다.

### 권한별 화면 분기 및 포인트 관리

- 마스터, 일반 사용자, 시스템 [[3단계 권한]]에 따라 접근 메뉴와 조회 범위를 분기하였습니다.  
  일반 사용자는 자사 데이터만, 마스터는 고객사를 선택해 조회합니다.
- 포인트 조회, 충전 이력, 충전 페이지를 구현하였습니다.  
  충전과 환불은 [[마스터 권한에서만]] 가능하도록 제한하였습니다.

### 프로젝트 운영

- 착수 시 엑셀 기반 [[WBS]] (Work Breakdown Structure)를 작성해 일정을 합의하였습니다.
- 인수인계용 빌드 가이드 README를 작성하였습니다.
- [[MUI]] 기반으로 화면을 구성해, 디자인 리소스 없이 짧은 기간 내에 구현하였습니다.
- [[반응형 웹]]으로 구성하여 다양한 디바이스에서 사용할 수 있도록 하였습니다.

## 🔧 기술 선택 및 설계 고민

### 문제 상황

- 로그인 후 화면을 새로고침하면 ==로그인이 풀리는== 문제가 있었습니다.  
  로그인 응답으로 받은 사용자 정보(권한 등급, 조회 가능한 고객사 목록 등)가 메모리에만 있었기 때문입니다.

### 해결 방법

- 사용자 정보를 브라우저에 그대로 저장하면 새로고침 문제는 해결되지만,  
  ==권한 정보가 클라이언트에 노출==되어 임의로 수정될 수 있다고 판단했습니다.
- 대신 ==세션 값만 저장==하고, 새로고침 시 그 값으로 사용자 정보를 다시 받아오는 방식을 제안했습니다.  
  클라이언트에는 검증 가능한 값 하나만 남고, 권한 판단은 서버가 담당합니다.
- 이를 위한 API가 없었기에 요청 및 응답 형태를 정리해 전달하였고, 백엔드에서 ==인증 갱신 엔드포인트==를 신설하였습니다.  
  이후 해당 요청이 들어올 때마다 세션 만료 시간도 함께 갱신되도록 협의하였습니다.
- 받아온 사용자 정보는 [[Redux]]로 전역 관리하여,  
  헤더의 포인트 표시, 메뉴 분기, 조회 조건 등 여러 화면에서 함께 사용하도록 하였습니다.

## 🔥 트러블슈팅

### CORS로 인한 인증 요청 차단

- 로그인 요청이 서버에 도달조차 하지 못하는 문제가 있었습니다.  
  서버가 ==Access-Control-Allow-Origin을 와일드카드("\*")로== 응답하고 있었는데,  
  자격 증명을 포함한 요청에는 와일드카드를 쓸 수 없어 브라우저가 차단하고 있었습니다.
- 허용 출처를 명시하도록 바꾸자 이번에는 ==preflight OPTIONS 요청이 정상 응답을 받지 못하는== 문제가 이어졌습니다.  
  본 요청 이전 단계에서 막히다 보니 body 데이터 자체가 서버에 전달되지 않았습니다.
- proxy 설정 유무에 따라 증상이 달라지는 점을 이용해,  
  ==클라이언트 원인과 서버 원인을 분리==해 정리한 뒤 백엔드에 전달했습니다.
  - proxy 미적용 시: CORS 차단 발생
  - proxy 적용 시: CORS는 통과하나 응답 이상
- 최종적으로 서버에서 요청 Origin을 그대로 반환하고 OPTIONS 요청에 정상 응답하도록 조정하여 해결하였습니다.
- 당시에는 개인 프로젝트에서 와일드카드로 모두 허용하면 대부분 동작했기에 원인 파악에 시간이 걸렸습니다.  
  이 과정에서 ==자격 증명이 포함된 요청에는 출처를 명시해야 하는 이유==를 이해하게 되었습니다.
